# Візуальний гід по дизайну квартири

Статичний сайт для обговорення дизайну квартири з дизайнеркою: ~90 м², 14-й поверх, ремонт від квітня, планування INSHA Design Studio (варіант 3, М 1:50).
Чистий HTML/CSS/JS без збірки фронтенду. Сайт відкривається з диска (`index.html`) і на GitHub Pages.

> Площі на сайті приблизні (±10%). Точні дані — у DWG дизайнера. Бюджетних сум у гіді немає й не повинно бути.

## Структура

```
index.html               головна: план, кімнати, палітра, формула смаку
data/site.json           назва, факти про квартиру, githubRepo для коментарів
data/rooms.json          перелік кімнат: id, slug, назва, площа, габарити, СТАТУС, положення на схемі
data/palette.json        загальна палітра квартири
data/taste.json          «формула смаку» і стилі 2026
data/bundle.js           ГЕНЕРУЄТЬСЯ build.mjs, вручну не редагувати
templates/room.html      єдиний шаблон сторінки кімнати
rooms/<slug>/index.html  ГЕНЕРУЄТЬСЯ з шаблону
rooms/<slug>/room.json   наповнення кімнати (стиль, палітра, матеріали, меблі, світло, питання, рішення)
rooms/<slug>/photos/     референси (фото)
rooms/<slug>/renders/    рендери від дизайнерки
plan/                    креслення: plan.svg або plan.png
build.mjs                скрипт збірки (Node.js 18+, без залежностей)
```

## Запуск збірки

```bash
node build.mjs
```

Запускайте після будь-якої зміни: нові фото, статус, `room.json`, нова кімната. Скрипт:
- створить папки `photos/`, `renders/` і порожній `room.json` для нових кімнат;
- перегенерує сторінки `rooms/<slug>/index.html` з шаблону;
- просканує фото й запише все в `data/bundle.js`;
- виведе підсумок по кімнатах і попередження (невідомий статус, не-зображення в папці тощо).

Переглянути локально: просто відкрийте `index.html` у браузері. Або через сервер:

```bash
python3 -m http.server 8000
```

Потім відкрийте http://localhost:8000.

## Як додати фото-референси

1. Покладіть файл у `rooms/<slug>/photos/`. Наприклад, ванна + туалет: `rooms/vanna-tualet/photos/`.
2. **Назва файлу = наш коментар до фото.** Розширення відкидається, решта показується на сторінці дослівно.
3. Пишіть вільним текстом, як говорите: `загалом, все подобається, окрім кольору плитки.jpg`.
   Скрипт ділить підпис на частини (по комах і перед «але», «крім», «окрім») і підсвічує кожну:
   - **плюс** (зелене): «подобається», «гарно / гарний / гарна», «все», «особливо»;
   - **мінус** (червоне): «не подобається», «не дуже», «не хочу», «забагато», «надто», «мало», «відсутність», «крім / окрім»;
   - частина без таких слів бере тон попередньої: у «подобається плитка, дзеркала» обидві частини будуть плюсом.

   Також працюють позначки в дужках: `(подобається)` / `(не подобається)`.
4. Групи на сторінці: «Подобається», «Є і плюси, і мінуси», «Не подобається», «Нейтральне».
5. Формати: jpg, jpeg, png, webp, gif, avif, svg.
6. Запустіть `node build.mjs`. Він покаже, скільки фото потрапило в кожну групу.

Якщо з назви тон не зрозумілий (наприклад, «те саме.jpg»), задайте його вручну в `rooms/<slug>/room.json`:

```json
"photoOverrides": {
  "те саме.jpg": { "tone": "like", "note": "Подобається те саме, що на попередньому фото" }
}
```

`tone`: `like`, `dislike` або `neutral`. `note` показується під підписом.

Рендери кладіть так само в `rooms/<slug>/renders/`: вони показуються окремим блоком «Рендери».

Slug-и кімнат: `vitalnia-kukhnia`, `spalnia`, `dytiacha-kabinet`, `peredpokii`, `vanna-tualet` (ванна й туалет поки однією сторінкою), `pralnia-komora`.

## Як змінити статус

У `data/rooms.json` змініть поле `status` потрібної кімнати на одне з трьох значень:

| Значення | Що означає | Вигляд |
|---|---|---|
| `ідея` | збираємо думки й референси | ○, пунктирна рамка |
| `вибираємо` | порівнюємо варіанти | ◆, крапкова рамка, вохра |
| `затверджено` | рішення прийнято | ●, суцільна рамка, шавлія |

Статус оновиться всюди: на схемі, у списку кімнат, у боковій панелі й на сторінці кімнати.
На GitHub Pages зміна в `rooms.json` видна одразу. Для перегляду з диска запустіть `node build.mjs`.

Там само задаються площа (`"area": 14.5`, поки `null` → «~ уточнити») і габарити (`"dimensions"`).

## Як наповнити кімнату

Редагуйте `rooms/<slug>/room.json`:

```json
{
  "style": {
    "directions": ["Japandi", "Warm minimalism"],
    "mood": "Тихо, тепло, багато дерева",
    "likes": ["що подобається: зведення по фото"],
    "dislikes": ["чого не хочемо"]
  },
  "palette": [{ "name": "Льон", "hex": "#E6DACB", "note": "стіни" }],
  "materials": { "floor": "…", "walls": "…", "ceiling": "…" },
  "furniture": ["…"],
  "lighting": ["…"],
  "questions": ["Чи вміщається пральна машина й сушарка колоною?"],
  "decision": { "summary": "…", "date": "…" }
}
```

Порожні поля показуються як «Ще не визначено» / «уточнити».

## Креслення

Покладіть `plan/plan.svg` (бажано) або `plan/plan.png`. Воно зʼявиться на головній на вкладці «Креслення».
Клікабельна «Схема» поряд залишиться умовною: прямокутники кімнат задаються полем `plan` у `data/rooms.json` (координати у полотні 1000×620).

## Коментарі (GitHub Issues)

> Репозиторій приватний, тож дизайнерка зможе відкрити Issue, лише якщо її додати в репо як collaborator (Settings → Collaborators).

У `data/site.json` вкажіть репозиторій: `"githubRepo": "логін/назва-репо"`.
Тоді кнопка «Прокоментувати» й посилання «відповісти» біля кожного питання відкриватимуть нове Issue з назвою кімнати в заголовку.
На `*.github.io` репозиторій визначається автоматично, але краще вказати його явно.
Щоб залишити коментар, дизайнерці потрібен акаунт GitHub.

## Публікація на GitHub Pages

> Для приватного репозиторію GitHub Pages доступні лише на платних планах GitHub (Pro / Team). Інакше: зробити репо публічним (тоді фото й бриф бачитимуть усі, хто має посилання) або надіслати дизайнерці PDF через друк сторінки.

1. Запустіть `node build.mjs` і закомітьте все, разом із `data/bundle.js` та `rooms/*/index.html`.
2. Запуште гілку на GitHub.
3. Repository → **Settings → Pages** → Source: *Deploy from a branch* → оберіть гілку й папку `/ (root)` → Save.
4. За хвилину-дві сайт буде за адресою `https://<логін>.github.io/<репо>/`.

Файл `.nojekyll` у корені вимикає обробку Jekyll, тож файли віддаються як є.

## Друк / PDF

Ctrl/Cmd + P → «Зберегти як PDF». Для друку приховуються навігація, кнопки й бічна панель, а кольори статусів і палітри зберігаються.
